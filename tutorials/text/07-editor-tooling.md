# Chapter 7: Editor Tooling

Framewerk provides Unity Editor wizards that automate the creation of scenes, UI components, and their integration with Addressables. These tools enforce consistent project structure and eliminate repetitive boilerplate.

## 7.1 Scene Wizard

The Scene Wizard creates a complete scene with all necessary bootstrapping code.

### Opening the Wizard

**Menu:** `Framewerk > Create Scene`

### Configuration Fields

| Field | Description |
|-------|-------------|
| **Scene Name** | Name for the scene (e.g., "Game", "MainMenu"). Used to generate class names |
| **Namespace** | C# namespace for generated code. Click "Auto" to derive from folder path |
| **Script Folder** | Where to save generated C# files (default: `Assets/Scripts`) |
| **Scene Folder** | Where to save the Unity scene file (default: `Assets/Scenes`) |

### What Gets Generated

When you click **Generate**, the wizard creates:

1. **`{SceneName}Bootstrap.cs`** — The MonoBehaviour entry point
   ```csharp
   public class GameBootstrap : ContextView
   {
       public ViewConfig viewConfig;
       private GameContext _context;

       private void Start()
       {
           _context = new GameContext(this, viewConfig);
           _context.Start();
       }
   }
   ```

2. **`{SceneName}Context.cs`** — The dependency injection context
   ```csharp
   public class GameContext : FramewerkMVCSContext
   {
       protected override void mapBindings()
       {
           base.mapBindings();
           injectionBinder.Bind<ViewConfig>().ToValue(_viewConfig);
           commandBinder.Bind<ContextStartSignal>().To<GameStartCommand>();
       }
   }
   ```

3. **`{SceneName}StartCommand.cs`** — The initialization command
   ```csharp
   public class GameStartCommand : Command
   {
       [Inject] public ViewConfig ViewConfig { get; set; }

       public override void Execute()
       {
           // Initialize your app here
       }
   }
   ```

4. **`{SceneName}.unity`** — The scene file with proper hierarchy:
   - Bootstrap GameObject (with ViewConfig component)
   - Camera3d
   - UICamera
   - UI Containers (Container3d, UiBottom, UiDefault, Popups, UiOverlay)

### Post-Generation Setup

After domain reload completes:
- The wizard attaches the Bootstrap component to the Bootstrap GameObject
- Wires the ViewConfig reference automatically
- Saves the scene
- Highlights the scene in the Project window

## 7.2 Component Wizard

The Component Wizard creates UI components (Views, Popups, Lists) with proper View/Mediator pairs, prefabs, and optional context bindings.

### Opening the Wizard

**Menu:** `Framewerk > Create UI Component`

### Wizard Sections

#### Component Section

| Field | Description |
|-------|-------------|
| **Name** | Component name without suffix (e.g., "Settings" becomes SettingsPopup) |
| **Type** | `Popup`, `List`, or `View` |

#### Paths Section

| Field | Description |
|-------|-------------|
| **Script Folder** | Destination for generated C# files |
| **Prefab Folder** | Destination for generated prefabs |

#### Code Generation Section

| Field | Description |
|-------|-------------|
| **Namespace** | C# namespace. Click "Auto" to derive from Script Folder path |
| **Setup in Context** | If enabled, auto-injects mediationBinder.Bind<>().To<>() into target Context |
| **Target Context** | Which Context class to inject bindings into |

#### Address Configuration Section

| Field | Description |
|-------|-------------|
| **Target Bootstrap** | ViewConfig to read ContextPrefixSO from |
| **Context Prefix (SO)** | Read-only display of the prefix from ViewConfig |
| **Custom Prefix** | Optional additional path segment (passed at runtime) |

### What Gets Generated by Type

#### Popup

**Scripts:**
- `{Name}View.cs` — Extends `PopupView`, implements `IPopupView`
- `{Name}Mediator.cs` — Extends `PopupMediator<T>`

**Prefab:** `{Name}Popup.prefab`
- Based on `PopupTemplate.prefab`
- Contains close button, title, background panel

**Addressable ID:** `{ContextPrefix}/UI/Popup/{Name}Popup`

#### List

**Scripts:**
- `{Name}ListView.cs` — Extends `ListView`
- `{Name}ListMediator.cs` — Extends `ListMediator<V, D>`
- `{Name}ListData.cs` — Implements `IListItemDataProvider`
- `{Name}ListItemView.cs` — Extends `ListItemView`
- `{Name}ListItemMediator.cs` — Extends `ListItemMediator<V, D>`

**Prefabs:**
- `{Name}List.prefab` — The list container with scroll rect
- `{Name}ListItem.prefab` — Individual item template

**Addressable IDs:**
- List: `{ContextPrefix}/UI/List/{Name}List`
- Item: `{ContextPrefix}/UI/List.ListItem/{Name}ListItem`

#### View

**Scripts:**
- `{Name}View.cs` — Extends `View`
- `{Name}Mediator.cs` — Extends `ExtendedMediator<T>`

**Prefab:** `{Name}.prefab`

**Addressable ID:** `{ContextPrefix}/UI/{Name}`

### Context Binding Injection

When **Setup in Context** is enabled, the wizard automatically:

1. Adds the using statement if missing:
   ```csharp
   using YourNamespace;
   ```

2. Injects the binding after the last existing binding:
   ```csharp
   mediationBinder.Bind<SettingsView>().To<SettingsMediator>();
   ```

For Lists, both main and item bindings are injected:
```csharp
mediationBinder.Bind<PlayerListView>().To<PlayerListMediator>();
mediationBinder.Bind<PlayerListItemView>().To<PlayerListItemMediator>();
```

## 7.3 Addressables Integration

Framewerk uses Unity Addressables for loading UI prefabs at runtime. The wizard integrates with this system automatically.

### Address Format

Default format: `[ContextPrefix]/[CustomPrefix]/UI/[TypeKey]/[ClassName]`

| Segment | Source |
|---------|--------|
| **ContextPrefix** | From `ViewConfig.ContextPrefixSO.Prefix` |
| **CustomPrefix** | Optional, passed at runtime |
| **UI** | Hardcoded root segment (always present) |
| **TypeKey** | Derived from component type |
| **ClassName** | Derived from C# class name |

### TypeKey Values

| Component Type | TypeKey |
|----------------|---------|
| View | *(empty)* |
| Popup | `Popup` |
| List | `List` |
| ListItem | `List.ListItem` |

### Example Addresses

| Component | ContextPrefix | Address |
|-----------|---------------|---------|
| SettingsView | `Game` | `Game/UI/Settings` |
| SettingsPopup | `Game` | `Game/UI/Popup/SettingsPopup` |
| PlayerList | `Game` | `Game/UI/List/PlayerList` |
| PlayerListItem | `Game` | `Game/UI/List.ListItem/PlayerListItem` |

### ContextPrefix ScriptableObject

Create via: **Assets > Create > Framewerk > Context Prefix**

```csharp
[CreateAssetMenu(fileName = "ContextPrefix", menuName = "Framewerk/Context Prefix")]
public class ContextPrefix : ScriptableObject
{
    public string Prefix;  // e.g., "Game", "Menu", "Examples"
}
```

Assign to `ViewConfig.ContextPrefixSO` on your Bootstrap GameObject.

### AddressBuilder API

```csharp
// Build address using ViewConfig settings
string address = AddressBuilder.BuildAddress(viewConfig, typeKey, className);

// Build with optional custom prefix
string address = AddressBuilder.BuildAddress(viewConfig, customPrefix, typeKey, className);

// Direct build without ViewConfig
string address = AddressBuilder.BuildAddress(contextPrefix, customPrefix, typeKey, className);
```

### Custom Address Patterns

For non-standard address formats, create an **AddressResolverConfig**:

**Menu:** **Assets > Create > Framewerk > Address Resolver Config**

```csharp
[CreateAssetMenu(menuName = "Framewerk/Address Resolver Config")]
public class AddressResolverConfig : ScriptableObject
{
    // Pattern with token placeholders
    public string Pattern = "{ContextPrefix}/{CustomPrefix}/UI/{TypeKey}/{ClassName}";
    
    // How to handle empty tokens
    public EmptyTokenBehavior EmptyTokenBehavior = EmptyTokenBehavior.Skip;
    
    // Path separator
    public string Separator = "/";
}
```

Available tokens: `{ContextPrefix}`, `{CustomPrefix}`, `{UI}`, `{TypeKey}`, `{ClassName}`

Assign to `ViewConfig.AddressResolver` to use custom patterns.

## 7.4 ViewConfig

ViewConfig is the central configuration component for UI setup in each scene.

### Inspector Fields

#### Addressable ID Configuration

| Field | Description |
|-------|-------------|
| **Context Prefix SO** | ScriptableObject reference for the context prefix |
| **Address Resolver** | Optional custom pattern resolver |

#### Cameras

| Field | Description |
|-------|-------------|
| **Camera3d** | World-space camera reference |
| **UICamera** | Orthographic camera for UI rendering |

#### UI Containers

| Field | Description |
|-------|-------------|
| **Container3d** | Transform for 3D UI elements |
| **UiBottom** | Transform for bottom-anchored UI |
| **UiDefault** | Default transform for standard UI |
| **Popups** | Transform for popup stacking |
| **UiOverlay** | Transform for always-on-top elements |

### Properties

```csharp
// Get UI camera dimensions
float height = viewConfig.UiCameraHeight;  // orthographicSize
float width = viewConfig.UiCameraWidth;    // Calculated from aspect ratio
```

### Scene Hierarchy

Recommended structure (created by Scene Wizard):

```
Bootstrap                 (ContextView, ViewConfig)
├── Camera3d              (Camera)
├── UICamera              (Camera, orthographic)
└── Canvas
    ├── Container3d       (referenced by ViewConfig)
    ├── UiBottom          (referenced by ViewConfig)
    ├── UiDefault         (referenced by ViewConfig)
    ├── Popups            (referenced by ViewConfig)
    └── UiOverlay         (referenced by ViewConfig)
```

## 7.5 Skin System

Projects can override default templates with custom prefabs.

### Creating a Skin

1. **Create SkinConfig:** Assets > Create > Framewerk > Skin Config
2. **Place it:** `Assets/Settings/Framewerk/SkinConfig.asset` (auto-discovered)
3. **Assign templates:** Override any template you want to customize

### SkinConfig Fields

| Field | Description |
|-------|-------------|
| **Skin Name** | Display name for the skin |
| **Description** | Optional description |
| **Popup Template** | Override for popup component template |
| **List Template** | Override for list component template |
| **ListItem Template** | Override for list item template |
| **Screen Template** | Override for screen/panel template |
| **View Template** | Override for basic view template |

### Resolution Order

1. Check project's `SkinConfig` for template override
2. If not found, use framework default from `Packages/com.dyskotron.framewerk/Editor/Wizards/Templates/`

## 7.6 Namespace Auto-Resolution

The "Auto" button derives namespace from folder path:

| Folder Path | Resolved Namespace |
|-------------|-------------------|
| `Assets/Scripts/Game/UI` | `Game.UI` |
| `Assets/Scripts/Features/Player` | `Features.Player` |
| `Assets/Game/Systems/Audio` | `Game.Systems.Audio` |

Logic: Skip "Assets" and "Scripts" segments, join remaining with dots.

## 7.7 Best Practices

### Project Setup

1. **Create ContextPrefix assets** for each major area of your game
2. **Organize scripts** in feature folders that map to namespaces
3. **Set up a SkinConfig** if you need custom UI templates
4. **Use consistent naming** — component names without type suffixes

### Wizard Workflow

1. **Open scene first** — The wizard needs a ViewConfig in the scene
2. **Set paths once** — Preferences are remembered between sessions
3. **Use "Auto" namespace** — Keeps naming consistent with folder structure
4. **Enable context binding** — Reduces manual wiring work

### Addressables

1. **Use ContextPrefix** to group assets by context/feature
2. **Keep addresses predictable** — Default format works for most cases
3. **Use CustomPrefix** for runtime grouping when needed
4. **Mark all UI prefabs** — Wizard does this automatically

## Summary

Framewerk's editor tools provide:

- **Scene Wizard** — One-click scene creation with Bootstrap, Context, and ViewConfig
- **Component Wizard** — Generate View/Mediator pairs with prefabs and bindings
- **Addressables Integration** — Automatic address generation and asset marking
- **ViewConfig** — Centralized scene configuration for cameras and UI containers
- **Skin System** — Override default templates with project-specific designs

These tools enforce consistent architecture while eliminating boilerplate code.
